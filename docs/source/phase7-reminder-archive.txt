==================================================
PART A — REMINDER
==================================================

Reminder must distinguish:

ReminderRule
!=
NotificationInstance

ReminderRule means:

"when / under what condition should the user be reminded?"

NotificationInstance means:

"a concrete reminder delivery occurrence."

Do NOT merge these concepts into one row.

==================================================
PERSISTENCE
==================================================

Hard rule:

REMINDERS MUST NOT LIVE ONLY IN MEMORY.

If LIFE HUD / scheduler restarts:

future reminders must still exist.

Use persistent database state as authority.

Use the existing Ship scheduler.

Do NOT introduce BullMQ or another queue system.

==================================================
SCHEDULER RECOVERY
==================================================

On scheduler restart:

reconstruct / reconcile pending ReminderRules.

Do not permanently lose future reminders.

Avoid duplicate delivery during restart recovery.

==================================================
DEDUPLICATION
==================================================

If the same logical reminder is requested twice accidentally because of:

browser retry
Lim retry
network retry
ActionGroup retry

do not generate duplicate identical notifications.

Use a sensible dedupe key / idempotency rule.

==================================================
PRIORITY
==================================================

Use a simple priority model equivalent to:

P0
P1
P2
P3

P0:
rare / genuinely critical

P1:
important

P2:
normal

P3:
low priority

Do not mark ordinary homework reminders P0.

==================================================
QUIET HOURS
==================================================

Support user-level or local configuration for quiet hours.

Example:

23:30–07:30

Normal reminders during quiet hours may:

- remain pending
- deliver silently
- delay to quiet-hours end

depending on a simple policy.

P0 may bypass quiet hours,
but P0 must be rare.

Do not build a huge notification preference system.
