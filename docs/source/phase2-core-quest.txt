==================================================
CRITICAL TASK INVARIANT
==================================================

PLANNED TIME != DEADLINE

These are different concepts.

Example:

Task:
高数第三章作业

plannedStart:
Thursday 19:00

dueAt:
Friday 23:59

If the user delays execution to Thursday 21:00:

plannedStart changes.

dueAt MUST remain Friday 23:59.

Never silently move a deadline because planned execution changed.

Add explicit tests proving this.

==================================================
OPTIMISTIC VERSIONING
==================================================

Important mutable records must support optimistic concurrency.

Example:

stored version = 3

client updates expecting version = 2

Result:

CONFLICT

Do NOT silently overwrite.

Implement this at least for Task.

Prefer patterns reusable by future important entities.

==================================================

==================================================

Tasks and important life records should default to soft delete where practical.

Normal queries must omit deleted records.

Do NOT implement the full future privacy hard-delete system yet.

Leave architecture compatible with it.
